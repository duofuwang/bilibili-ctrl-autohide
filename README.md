# bilibili 网页全屏控制栏自动隐藏修复

修复 B 站网页全屏下，鼠标从窗口底部缓慢移出后底部播放条卡住不自动隐藏的问题。

## 现象

- 网页全屏（或全屏）下把鼠标从窗口底部缓慢移出，底部播放条卡住不自动隐藏；
- 快速移出时一切正常。

## 原因

控制栏一旦被判定为「鼠标悬停中」，只有它自己收到 `mouseleave` 才会取消该状态，而此时自动隐藏的定时器已经被取消。指针从窗口底部缓慢移出时，这个事件不保证能到达元素，悬停状态就被永久保留。快速移出因为不经过控制栏区域，由定时器正常收起，所以看起来是「快的没事、慢的卡住」。

## 安装

1. 先装一个用户脚本管理器：Tampermonkey（篡改猴）、Violentmonkey（暴力猴）或脚本猫；
2. 二选一安装本脚本：
   - 本仓库直装（推荐，国内可直连）：`https://cdn.jsdelivr.net/gh/duofuwang/bilibili-ctrl-autohide@main/bilibili-ctrl-autohide.user.js`
   - GreasyFork：待补充（从那里安装的用户会自动更新）

## 工作原理

检测到「指针已离开窗口」后，给播放器自己的画面区和控制栏补发一次离开事件，让播放器原本的自动隐藏逻辑恢复工作。不改样式、不改播放器其它行为。

判断「指针已离开窗口」的两种方式：

1. 优先使用浏览器派发的移出事件（`mouseleave`，或 `relatedTarget` 为空的 `mouseout`）；
2. 部分环境下浏览器不派发，则用兜底规则：指针进入窗口边缘 4 像素内，且随后 300 毫秒内没有新事件、也没有按住鼠标键。

只在指针最后一次位置落在播放器范围内时才动手，正常悬停、拖动进度条、点击按钮都不受影响。

## 调试

触发时会向控制台打印一行：

```
[bili-ctrl-autohide] released control hover (原因)
```

括号里是触发路径（`mouseleave` / `mouseout-null` / `edge-quiet`）。如果播放条仍然卡住，把这行发到 Issues 有助于定位。

## 已知边界

- 中等速度移出（既没触发浏览器移出事件、也没经过边缘判定带）仍可能不触发，可以把脚本里的 `EDGE_PX` 从 4 调大；
- 只处理控制栏自动隐藏这一个问题，不包含其它播放器改动。

## 验证情况

在 Edge（Chromium 内核）上用真实播放器复现了问题，并对「缓慢移出会收起、正常悬停不误收、快速移出正常收起」三种场景做了修复前后的对比验证。
